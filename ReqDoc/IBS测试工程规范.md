# IBS 测试工程规范

版本 v0.1 ｜ 2026-11-21 ｜ 当前范围：preparation / completion；参数见 [IBS 参数文件规范](IBS参数文件规范.md)，函数见 [函数接口规范](函数接口规范.md)，变量规范后续补充

## 1. 前提与总则

1. 新工程独立新建，旧工程保留不动，不做就地改造。
2. **平台已验证：用例失败或中止时 completion 仍会执行。** 因此清理逻辑只放 completion 一份，用例体不再写失败清理副本。
3. preparation / completion 是所有序列共用的固定段；唯一允许的差异是 `StartLog` 的序列名参数。
4. 两段内只做“置状态 + 记录”，不做合格判定、不做重试、不做业务等待。
5. 任何一步失败都要记录：prep 失败则不再进入测量，completion 失败单独记“清理失败”，不得把主用例判成通过。

## 2. 状态定义

| 状态 | 含义 | 继电器命令元组（电池, CAB1500, IBS） | 预期实际状态（待台架确认） |
|---|---|---|---|
| S0 安全态 | 测试结束 / 异常收尾 | (0, 1, 1) | 电池断开、CAB1500 断电、IBS 断电 |
| S1 准备态 | 用例开始前 | (0, 1, 0) | 电池断开、CAB1500 断电、IBS 接入电源轨（输出未开） |
| S2 测试态 | 用例体控制 | 由用例决定 | 按用例设压 / 限流 / 输出 / LIN |

- 元组是**命令值**，不是触点实测；常闭触点下 1 可能代表断电，必须按接线图核对后固化。
- 旧工程存在 `(0,0,0)`、`(0,1,0)`、`(0,0,1)` 三种写法；新工程只允许 S0 / S1 两个预置元组，S2 由用例体显式改变并记录。

## 3. preparation 固定内容（5 步）

| # | 动作 | 调用 | 目的 | 失败处理 |
|---:|---|---|---|---|
| 1 | 开启本次日志 | `StartLog(<序列名>)` | 记录后续命令和执行结果 | 准备失败 |
| 2 | 先停 LIN 调度 | `LIN_Stop()` | 总线置静默，杜绝后台节点抢调度 | 记录，不阻断 |
| 3 | 禁用唤醒节点 | `SNAP_WakeNode(OFF)` | 防止 `ECU_LIN_WakeUp` 自动开表 | 必须成功 |
| 4 | 确保输出关闭 | `PWR_Off()` | 配置参数前不得有输出 | 必须成功 |
| 5 | 继电器到准备态 | `RELAY_Set(IDLE)` | 电池断开、CAB1500 断电、IBS 接入 | 必须成功 |

```text
PHASE_Prepare(name):
    StartLog(name)
    PHASE_ValidateParams()      // 内部校验，不计入 5 步
    LIN_Stop()
    SNAP_WakeNode(OFF)
    PWR_Off()
    RELAY_Set(IDLE)             // S1
```

`PHASE_ValidateParams()` 是函数内部校验，不是第 6 步：只读 `TB_*` 参数并比较，不碰设备，幂等、无副作用。执行位置固定在 `StartLog` 之后、`LIN_Stop` 之前；失败即“准备失败”，后续步骤不执行，completion 仍会执行。保留该函数。

约束：

- 不设电压、不开输出、不开 LIN、不接真实电池、不做长延时。
- 顺序不可改：日志最先，紧接着参数校验，然后 LIN 先停，输出先关，最后切继电器。
- 整段由 `TB_PrepTotalTimeout_ms` 约束，不允许出现业务延时。

## 4. completion 固定内容（5 步）

| # | 动作 | 调用 | 目的 | 失败处理 |
|---:|---|---|---|---|
| 1 | 停 LIN 调度 | `LIN_Stop()` | 先静默总线，避免断电期间刷错误帧 | 记录，继续 |
| 2 | 关输出并等电压回零 | `PWR_Off()`；`PWR_WaitZero()` | 按 `TB_DvmZeroTolerance_V`、`TB_DvmZeroTimeout_ms` 判定回零 | 超时记清理失败，继续 |
| 3 | 继电器到安全态 | `RELAY_Set(SAFE)` | 电池、CAB1500、IBS 全部断开 | 记清理失败，继续 |
| 4 | 禁用唤醒节点 | `SNAP_WakeNode(OFF)` | 双保险，防止收尾期间被拉起 | 记录，继续 |
| 5 | 停止日志 | `StopLog()` | 最后一步，保留全部清理记录 | 记清理失败 |

```text
PHASE_Complete():
    LIN_Stop()
    PWR_Off()
    PWR_WaitZero()          // 有界，超时记清理失败
    RELAY_Set(SAFE)         // S0
    SNAP_WakeNode(OFF)
    StopLog()
```

约束：

- completion 只做清理和记录：不做合格判定、不做重试、不做业务等待。
- 唯一允许的等待是电压回零，必须有界；超时写报告，不无限等。
- 每步幂等：已停的 LIN、已关的输出、已在安全态的继电器，再执行不报错。
- prep 在 `StartLog` 阶段失败、日志未打开时，`StopLog` 必须能安全返回，不得因此产生二次异常。
- 清理失败单独给 verdict（如 `CleanupFailed`），与主用例结果分开记录。

## 5. 禁止放进这两段的内容

| 内容 | 放哪里 | 原因 |
|---|---|---|
| 电压点设置、升压 / 降压 | 用例体 | 属于测量条件，各用例不同 |
| `PWR_On()` / 开输出 | 用例体 | 开输出即开始供电，是测试动作 |
| `LIN_OpenNormal()`、等帧 | 用例体 | 通讯建立属于判据 |
| 连接真实电池 | 用例体 | 改变供电拓扑，受 10~15.5 V 限制 |
| 稳定延时、静置、等唤醒 | 用例体 | 属于测量流程 |
| 合格判定、重试、报告结论 | 用例体 | 清理段不得改变主判定 |
| 多轮循环 | 用例体 | 循环是测试逻辑 |

## 6. 接口与命名

函数登记、命名前缀、调用规则统一见 [函数接口规范](函数接口规范.md)。硬约束只有三条：

1. preparation / completion 各只允许一个元素：`PHASE_Prepare` / `PHASE_Complete`。
2. body 只允许调用登记表中“VTT 可见=是”的函数。
3. 不可见函数只能被其他函数调用，不得直接写进 XML。

第 3、4 节写的是逻辑步骤（各 5 步），落地形态是各 1 个 `PHASE_*` 单入口，步骤细节进日志；对应关系见函数登记表。

建议新增只读回读变量：由 `Relay4C_Proc` 把 `relay_get_all()` / `relay_read_inputs()` 发布为 `Power_RelayCrtl::RelayReadback`、`InputReadback`，让 prep / completion 能核对“命令 vs 实际”，而不是只看命令值。旧工程没有这个能力。

参数定义、命名、归属、函数槽位与校验规则见 [IBS 参数文件规范](IBS参数文件规范.md)。

## 7. 旧工程问题对照

| 旧问题 | 新设计 |
|---|---|
| 每个序列复制 8 步，改一处要改 11 处 | 只保留 `PHASE_Prepare` / `PHASE_Complete` 两份实现 |
| 继电器元组三种写法混用 | S0 / S1 固定元组 + 枚举，用例体不得直接写通道 |
| 有的序列 completion 漏停 LIN / 漏切安全态 | 固定 5 步不可跳过 |
| `ECU_LIN_WakeUp` 后台抢 LIN | prep 第 3 步 `SNAP_WakeNode(OFF)` |
| 收尾超时写死魔法数 | 超时进 vparam，代码不写死 |
| completion 里做判定 / 重试 | 清理与判定彻底分离 |
| 失败后无统一清理 | 平台保证 completion 执行，清理只保留一份 |
| 参数散落 | 全部进 vparam，序列只引用 |

## 8. 用例体变体（不改 prep / completion）

| 用例类型 | 用例体首步 | 用例体末步 |
|---|---|---|
| 休眠电流类 | 设压 → 开输出（LIN 保持停） | 直接结束，completion 收尾 |
| 需要 LIN 通讯类 | `PWR_On()` → `LIN_OpenNormal()` | 保持到观察结束 |
| 需要真实电池类 | 先设 10~15.5 V 且输出关 → 闭电池继电器 → 开输出 | 先关输出，再交给 completion 断电池 |

## 9. 上台架前必须确认

1. `(0,1,0)` / `(0,1,1)` 对应的实际触点状态，按接线图实测，不能只看命令值。
2. completion 里 DVM 回零的 1000 ms 是否够（受 N8361 回读周期限制）。
3. 是否新增 `RelayReadback` / `InputReadback`；不加则“命令成功”不等于“触点到位”。
